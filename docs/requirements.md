## 1. 背景与现状

MoyuyuPet 是一个桌面宠物项目。工程最初是 WPF 空模板，2026-11 已迁移为 Tauri 2 + Vue 3 + TypeScript，目前只有可运行的空骨架，没有业务逻辑。

目标是把 MoyuyuPet 做成一只"AI 时代的桌面小宠物"：用户在本地使用 AI 编程工具时，宠物能感知 token 消耗和任务进展，用可爱的动画和少量吐槽气泡给出即时反馈。

2026-11-02 已在本机确认以下数据信号（只读取了结构与计数，未读取对话内容）：

- Qoder CN：本地 SQLite 中有逐条 assistant 消息的 token 统计。
- DeepSeek Harness（dsh）：本地会话文件中有 turn/step/tool 事件和 usage 字段。
- Codex：本机为 SQLite 形态，`threads` 表有累计 token 字段；经典 JSONL 形态需按版本兼容。
- Claude Code：本机未安装，但官方提供 hooks、transcript 与 OpenTelemetry 三种可观测入口。

因此"检测本地 token 消耗"在技术上可行，主要复杂度在适配不同工具的数据格式。

## 2. 产品定位

- 一句话：把 AI 编程时看不见的 token 消耗，变成桌面上看得见、有情绪的小宠物反馈。
- 目标用户：每天使用 Qoder、DeepSeek Harness、Claude Code、Codex 等 AI 编程工具的开发者，首先服务作者本人。
- 核心体验：
  - AI 开始干活：宠物进入工作状态，敲键盘、吃东西或忙碌。
  - token 快速消耗：宠物表现得心疼钱，动画强度随消耗速率变化。
  - 任务完成：宠物庆祝，并偶尔冒出一句与任务相关的"小笨蛋看法"。
  - 没有活动：宠物发呆、打瞌睡，不打扰用户。
- 设计原则：
  - 本地优先：默认不联网、不读对话正文、不上传任何数据。
  - 低打扰：动画克制，气泡有冷却和优先级，不抢焦点。
  - 可扩展：新增一个 AI 工具只需要增加一个适配器。
  - 健壮：任何适配器失败都不能影响宿主 AI 工具，也不能让宠物崩溃。

## 3. 目标与非目标

### 3.1 本期目标

1. 支持 Qoder（含 Qoder CN）的 token 消耗检测。
2. 支持 DeepSeek Harness（dsh）的 token 消耗与任务事件检测。
3. 提供可扩展适配器框架，后续接入 Claude Code、Codex 及更多工具。
4. 实现透明、置顶、可拖动的 2D 宠物窗口，以及工作/庆祝/闲置等动画状态。
5. 实现低频、可配置、与任务相关的评价气泡。
6. 提供托盘、暂停、设置、开机自启、单实例等日常使用能力。
7. 默认本地处理，提供明确的隐私开关。

### 3.2 非目标（本期不做）

- 不做完整的 token 用量统计面板或账单系统。
- 不通过代理、TLS 中间人或修改 AI 工具的方式截获请求。
- 不做屏幕 OCR 或读取剪贴板来推测任务。
- 不做 BongoCat 式的全局键盘/鼠标镜像（列为后续可选）。
- 不做账号、云同步、多端同步。
- 不默认调用云端大模型生成气泡文案。
- 不承诺首期支持 macOS/Linux，首发以 Windows 10/11 x64 为准。

## 4. 用户故事与验收

| 编号 | 用户故事 | 验收标准 |
| --- | --- | --- |
| US-01 | 我在 Qoder 里让 AI 改代码，希望宠物能立刻有反应 | token 增量被检测后 1 秒内触发工作动画 |
| US-02 | 我在 dsh 里跑一个任务，希望宠物知道任务在进行、完成了 | turn/step 事件能驱动工作与庆祝状态 |
| US-03 | 我同时开着两个 AI 工具，希望宠物不要抽风 | 多来源事件被聚合，不重复播放同一段动画 |
| US-04 | 我希望宠物不要在启动时把历史记录当成新任务 | 首次启动和重启后不回放历史 token |
| US-05 | 我在开会时希望宠物安静 | 暂停后停止动画和气泡，适配器停止或静默 |
| US-06 | 我没装某个 AI 工具时，宠物仍能正常使用 | 适配器显示"未检测到"，不影响其他功能 |
| US-07 | 我不想被气泡刷屏 | 同一时间最多一个气泡，默认冷却不少于 40 秒 |
| US-08 | 我担心隐私 | 默认只读元数据，不读正文、不联网、不上传 |

## 5. 功能需求

优先级：P0 为首版必须，P1 为首版尽量，P2 为后续增强。

### FR-1 事件采集（P0）

- FR-1.1 支持 Qoder / Qoder CN：读取本地只读数据库，按新增 assistant 消息统计 token。
- FR-1.2 支持 dsh：读取本地会话事件，识别 turn/step/tool 和 usage。
- FR-1.3 支持 Claude Code：优先使用 hooks + transcript；OpenTelemetry 作为 P2 增强。
- FR-1.4 支持 Codex：按本机形态选择 SQLite 或 JSONL/notify 适配方式。
- FR-1.5 提供统一适配器接口：每个工具独立模块，可探测、可启停、可报告健康状态。
- FR-1.6 适配器失败隔离：单个工具解析失败只影响自身，不阻塞其他适配器，不导致应用退出。
- FR-1.7 读取水位：为每个数据源持久化读取位置，启动时跳过历史数据。
- FR-1.8 去重：同一请求/消息/事件只能计数一次，避免流式或多轮写入造成重复。

### FR-2 归一化与聚合（P0）

- FR-2.1 统一 token 口径：输入、输出、缓存读、缓存写；无法区分的字段允许为 0。
- FR-2.2 统一事件类型：任务开始、token 增量、工具调用、任务结束（成功/失败）。
- FR-2.3 时间窗口聚合：建议 200–500ms 聚合一次，禁止逐 token 触发动画。
- FR-2.4 消耗速率：以单位时间 token 增量作为动画强度，而不是绝对累计值。
- FR-2.5 多会话：支持多个会话同时进行；首版可合并为一只宠物的总活跃度。
- FR-2.6 静默判定：超过一定时间无事件进入闲置，更长时间进入睡眠。

### FR-3 宠物表现（P0）

- FR-3.1 窗口：透明、无边框、置顶、不显示在任务栏，可拖动，位置可记忆。
- FR-3.2 点击穿透：非交互区域不拦截鼠标；宠物本体可点击、可拖动。
- FR-3.3 动画状态：至少包含 idle、working、celebrate、error、sleep 五种状态。
- FR-3.4 强度映射：working 状态的动画速度/幅度随 token 速率变化，并有衰减。
- FR-3.5 状态优先级：任务结束庆祝优先于工作循环，错误状态优先于普通工作。
- FR-3.6 多显示器与高 DPI：窗口位置在 100%–200% 缩放下保持可用，重启后不跑到屏幕外。
- FR-3.7 渲染降级：Live2D 模型或运行时缺失时，自动回退内置 SVG 宠物，不影响事件与气泡。

### FR-4 评价气泡（P0）

- FR-4.1 触发时机：任务开始、token 里程碑、工具调用、任务完成、错误、长时间闲置。
- FR-4.2 内容来源：默认使用本地模板 + 元数据（工具名、项目/任务标题、文件数、token 数、耗时、工具调用类型）。
- FR-4.3 禁止内容：默认不显示代码、prompt、文件内容、密钥、完整路径；任务标题截断到 24 字并可关闭。
- FR-4.4 频率控制：同一时间最多一个气泡；默认冷却 40 秒；按优先级排队并丢弃低优先级。
- FR-4.5 文案风格：可爱、略带"小笨蛋/心疼钱"人格，长度建议不超过 30 个汉字。
- FR-4.6 可关闭：用户可关闭气泡，或调整频率。
- FR-4.7 本地模型（P2）：可选接本地小模型生成文案，禁止默认上传任何内容。

### FR-5 控制与设置（P1）

- FR-5.1 托盘菜单：显示/隐藏宠物、暂停/恢复、设置、退出。
- FR-5.2 设置窗口：适配器开关与路径、气泡频率、隐私选项、开机自启、动画强度。
- FR-5.3 单实例：重复启动时唤醒已有窗口，不启动第二个宠物。
- FR-5.4 开机自启：可选，默认关闭。
- FR-5.5 退出语义：关闭窗口默认隐藏到托盘，托盘菜单提供真正退出。
- FR-5.6 适配器状态：设置页显示每个工具"已连接/未检测到/解析失败/已暂停"。

### FR-6 隐私与安全（P0）

- FR-6.1 默认不联网；除用户显式开启的功能外，不发起任何外部请求。
- FR-6.2 默认只读元数据（工具名、token、会话标题等）；不读取、不落盘、不上传对话正文和代码。
- FR-6.3 hook/插件写入本地收件箱时使用原子写入；如启用本地 HTTP，仅绑定 127.0.0.1 并带随机令牌。
- FR-6.4 设置页明确说明每个工具读取了哪些文件/字段。
- FR-6.5 本地日志只记录适配器状态和错误类型，不记录正文。
- FR-6.6 卸载或清空数据时，删除水位、设置和本地日志。

### FR-7 可选增强（P2）

- FR-7.1 Claude Code OpenTelemetry 精准用量与成本。
- FR-7.2 本地小模型生成气泡文案。
- FR-7.3 Live2D 模型与动作（已接入 Tororo 白猫，模型缺失时回退 SVG）。
- FR-7.4 音效、成就、每日 token 小结。
- FR-7.5 BongoCat 式全局键鼠镜像。
- FR-7.6 多宠物/按工具分宠物。
- FR-7.7 macOS/Linux 支持与自动更新。

## 6. 非功能需求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-1 | 性能 | 闲置 CPU ≤ 1%，工作态 CPU ≤ 5%，常驻内存 ≤ 250MB |
| NFR-2 | 延迟 | 从检测到事件到动画开始 ≤ 1 秒（Qoder 轮询可放宽到 1.5 秒） |
| NFR-3 | 启动 | 冷启动到宠物可见 ≤ 3 秒 |
| NFR-4 | 稳定性 | 单条坏数据被跳过；适配器异常不导致应用退出；连续运行 24 小时无泄漏 |
| NFR-5 | 兼容性 | Windows 10/11 x64；WebView2；100%–200% DPI；多显示器 |
| NFR-6 | 可扩展性 | 新增一个适配器只需一个模块 + 一份 fixture + 一条设置项 |
| NFR-7 | 可观测性 | 本地可查看适配器状态、最近事件时间、解析错误计数 |
| NFR-8 | 打包 | 提供安装包，无需管理员权限；卸载干净 |

## 7. MVP 验收清单

- [ ] 宠物窗口透明、置顶、可拖动、默认点击穿透。
- [ ] Qoder 产生新 token 后 1.5 秒内宠物进入 working。
- [ ] dsh 的 turn/step 事件能驱动 working/celebrate。
- [ ] 气泡最多 40 秒一次，内容不包含代码或 prompt。
- [ ] 重启应用后不回放历史 token。
- [ ] 同时开启 Qoder 与 dsh 不重复计数、不重复动画。
- [ ] 暂停、隐藏、退出、开机自启、单实例均可用。
- [ ] 未安装 Claude Code / Codex 时界面显示"未检测到"，不影响其他功能。
- [ ] 断网状态下全部核心功能可用。

## 8. 开放问题

1. 宠物美术方案：先精灵图，还是直接上 Live2D？由谁产出素材？
2. 一只宠物聚合所有工具，还是每个工具一只？
3. 气泡的默认语言、语气强度、是否允许出现项目名？
4. 是否允许可选接入云端模型生成文案？默认应为关闭。
5. 首发是否只做 Windows，macOS/Linux 排到什么时候？
6. 是否要把 BongoCat 式键鼠镜像纳入路线图？
7. Codex 优先支持桌面版还是 CLI 版？
8. Claude Code 的 hook 安装方式：自动修改 settings.json，还是提供手动配置说明？
9. 是否需要保留历史用量用于"每日小结"，保留多久，如何清理？
